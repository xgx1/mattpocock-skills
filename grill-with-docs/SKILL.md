# Grill With Docs

把「拷问需求」和「沉淀文档」合成一个动作：每一轮追问既打磨需求，又把已经锁定的决策写进文档。

## 第一步：并行加载两个技能

调用 Skill 工具两次，分别加载 "grilling" 和 "domain-modeling"，然后按两者的纪律执行：

- **grilling** 提供拷问方式：多轮提问、每轮抛出整个前沿（frontier）、每个问题附推荐答案、等用户回答后再下一轮。
- **domain-modeling** 提供文档落点：随着决策被敲定，随手记录 ADR 和术语表（CONTEXT.md），让"拷问的副产品"成为项目的长期资产。

## 触发时机

- 用户提出新需求 / 新功能 / 想法 / 方案 / 改动（无论大小）。
- 用户说"我想做 X""加个功能""帮我实现""先过一遍需求"。
- 在开始任何实现（写代码、制定计划、生成 TODO）**之前**运行——这是门禁，不是事后复盘。

## 不触发的情形

- 纯闲聊、纯事实问答、与项目无关的咨询。
- 用户已经明确说"需求已确认，直接做"（此时仍可在动手前用一句话确认关键歧义，不要开完整拷问）。

## 出口条件

满足以下全部条件才允许进入实现：

1. 需求的核心歧义已被追问清除（或用户明确接受默认）。
2. 关键决策已写成 ADR，新术语已进术语表。
3. 向用户复述一遍最终需求（一句话级别），得到"可以"后，才交接给下一步（制定计划 / 实现）。
